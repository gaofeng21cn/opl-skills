# 开发环境与制作资产

## 包、构建与测试

先看任务、引用和使用频率，再用原生清理能力：uv/pip/npm下载缓存、Go构建缓存、Homebrew cleanup/autoremove等各有职责。当前环境、包本体与下载缓存分开；不把Conda `pkgs` 整目录删除，先看环境链接关系和官方预演；Homebrew旧keg核对活跃进程打开的库、虚拟环境解释器链接与固定版本脚本。`npx` 可能直接承载正在运行的MCP，核对进程、配置和命令软链接，不能与npm下载缓存一起全删。

CI制品缓存先看下载器缺失重下载、校验能力和活跃Runner.Worker；控制文件、锁、分段下载和在用压缩包保留。7天或30天只是历史选择，根据容量预算、最近使用、重下载成本和任务状态选范围。正在升级的新软件暂存由更新流程收尾，不按“旧文件”删除。

测试目录先确认生成代码、当前作业、Git改动与唯一诊断。Git忽略、`tmp`/`out` 前缀或过期时间不是删除依据。空树用 `rmdir`；非空残留按精确清单处理。重复 `mkdtemp` 堆积追到测试helper的 `finally`/退出清理，失败诊断单独导出，保留生产者修复是否已合入/安装的证据，不以一次清除代替修复。

工作树和源码归所属任务处理；不能用整盘清理绕过未吸收改动。临时patch仅在证明有效成果已在当前源码或可达Git历史保留，或已被明确替代时删除。

## 浏览器和日志

Chrome签名克隆先核对真实Google应用身份、版本、位置及打开路径；保留使用中的克隆，不触碰用户profile。历史实测正常关闭会清理而强杀会残留；先改善自动化正常关闭，功能开关需检查当前Chrome实现和实际启动入口，不能把某次旧flag永久套入全部浏览器。重复出现还需检查其他入口和存量会话。

异常日志通过目录、持续写入进程及调试配置确认，必要时正常退出应用后处理。Mail历史曾因调试开关持续写入约11 GB；关闭已确定的调试入口才减少再增长。应用容器里的聊天媒体、邮件数据库和凭据继续按所属应用管理，不因名称含缓存而全删。

## Docker与VM

优先 `docker system df -v`、容器/卷/镜像inspect，逐个记录精确ID。零引用或RECLAIMABLE只说明引擎引用关系，PostgreSQL卷也可能保存业务数据；结合Compose标签、任务来源和卷内容确认用途。历史“全部开发测试”的结论不能覆盖后来出现的持久业务数据。可重建测试数据按已授权范围删除；确有保留价值的状态使用一致性备份后迁移。运行中数据库不靠活拷贝文件证明备份有效。

操作交给引擎原生接口，不直接删除Docker.raw内文件、不使用连具名卷一起扫掉的全量prune。保留脚本依赖的本地镜像（例如 `--pull=never`）和当前业务卷。引擎无响应先区分UI与daemon；只读检查盘内数据也需已停止、文件系统干净等条件，不把修复Docker本身变成默认清理步骤。Docker对象回收、磁盘文件分配量和APFS可用量分别核对。

Tart看真实运行状态、生成任务、脚本引用和用户数据，停止状态及最近访问时间不能单独决定退役。保留在用干净基线；有保留价值的退役VM通过原生export/import并在隔离名称下恢复核对disk/NVRAM与配置差异，验证临时VM随后清理。磁盘已缺失、只剩config/NVRAM的残留也先排除当前引用和句柄。

## SQLite

区分数据库正文、WAL和空闲页。通过所属服务支持的维护方式处理WAL检查点或重建；活跃数据库及WAL/SHM不作为普通缓存文件删除。只读 `PRAGMA page_count; PRAGMA freelist_count; PRAGMA page_size;` 可辅助评估，空闲页为0不支持“压缩可回收大量空间”的结论。复制活跃数据库需要SQLite一致性备份机制。维护后的完整性与调用方使用情况都需回读；避免未经支持的VACUUM长时间阻塞活跃工作。

## 生产/审看工作区

从制作配置、project/score/current指针、交付manifest识别当前版本，不能按修改时间或文件名猜母版。当前源码、素材来源、配音、母版及文本审查结论保全；旧抽帧可按诊断价值缩减，留下紧凑contact/strip与归档指针或工具原有pruned标记。复用所属工作台生命周期工具，先预演再按当前集合执行；本Skill不自建制作状态机。

冻结的旧批次与活跃批次分开处理；执行前刷新状态，变化的候选跳过。前后核对实际受保护工程及交付字节，不把所有项目固定为某个历史数量。内容/哈希验证不能替代连续动态、声音或医学审查。
